02 · Three-tier dedup

先用低成本確定性比對，必要時才升級判斷

TIER 01

精確雜湊

Finding.hash 相同即重複。

檔案／位置／分類／內容雜湊
→
TIER 02

標題模糊比對

比較標題的 Levenshtein 相似度。

≥ 0.8 命中
→
TIER 03 · OPTIONAL

LLM 語意比對

LLM callback 判斷不同措辭是否同義。

每次去重上限 10 次
命中任一層 → 指向既有 Finding 全部未命中 → 保留為新 Finding

現況：CLI 尚未接上 semanticDedup，第三層尚未啟用。

03 · Disagreement

不靠多數決，讓每個意見都經過同一套判斷

收集審查

等 CI 與機器人評論，整理成 Finding。

分類問題

規則先判；需要時才交給 LLM。

人工決策

建議 fix / defer / reject；人可逐項覆寫。

三層去重

精確 hash → 標題相似度 → 可選語意。

檢查收斂

追蹤關鍵 Finding 與不變量；必要時停止並升級。

修復並回覆

每輪一個 commit，回覆後請機器人複查。

達停止條件：停止並升級人工判斷。 尚未收斂：回到 01，最多 3 輪。

04 · Hardest problem

「不同文字，究竟是同一個問題，還是兩個不同的 bug？」

去重太保守

同一缺陷被多個 reviewer 重複處理，製造噪音。

合併太積極

獨立缺陷或相反建議可能被錯誤吞掉。

解法：由精確 hash 到相似度，再到可選語意；控制成本與誤合併風險，邊界情況保留人工決策。

05 · Daily AI workflow

1 · CLAUDE.md

模組邊界、工程不變量、常用驗證命令。

2 · 聚焦 prompt

指定檔案範圍、預期行為、不可碰觸項目。

3 · 驗證

先測試，再最小修改，最後跑 bun run verify。

「只處理指定問題，先補失敗測試，再做最小修改；執行 bun run verify。證據不足就標示未知，不要自行補假設。」
